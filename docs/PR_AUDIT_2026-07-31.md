## Merged

### PR #3 — Avoid historical blocked Runs freezing the queue

URL: https://github.com/imtms/tagent-core/pull/3

Merge commit: `36d2fbe`

Decision: merge.

Automatic Session inbox dispatch now treats any running Run as active, but only lets the latest blocked/interrupted Run hold the queue. Older blocked/interrupted Runs remain durable for audit and manual recovery without permanently freezing newer Session work.

### PR #2 — Manually start a queued Supervisor input

URL: https://github.com/imtms/tagent-core/pull/2

Merge commit: `87015c5`

Decision: merge.

Adds `POST /api/sessions/:id/inbox/:itemId/start` and a Web `Run now` action. The claim, TaskRun creation, and Inbox binding are transactional. A running Run or active continuation still prevents concurrent execution. Continuation claim also checks for another running Run in the same Session.

This is an explicit human override of automatic blocked/interrupted priority, not a direct Pi prompt path: the selected Inbox item still becomes a durable TaskRun before Pi execution.

### PR #4 — Show latest TaskRun state in the workspace list

URL: https://github.com/imtms/tagent-core/pull/4

Merge commit: `7e3dae7`

Decision: merge.

Session summaries expose `latestRunStatus` and `latestRunPhase` through a correlated latest-Run query. The Web Session rail refreshes and displays compact status metadata without a schema migration or application-layer N+1 query.

## Changes requested

### PR #1 — Immutable production artifact and native dependency deployment

URL: https://github.com/imtms/tagent-core/pull/1

Decision: do not merge yet.

The fixed-runtime artifact direction is sound, but the current revision needs:

- committed, reproducible deployment integration tests for corrupt native bindings, manifest/checksum failures, and `node --check` failures;
- preservation and atomic restoration of the previous `current` symlink when service restart or HTTP health verification fails;
- tar entry validation against absolute paths, `..` traversal, and escaping symlink/hardlink targets;
- broader manifest coverage for the release file set, or a documented integrity model explaining the deliberately limited set.

A blocking review comment was posted on the PR.

### PR #5 — Persisted current-operation progress

URL: https://github.com/imtms/tagent-core/pull/5

Decision: do not merge yet.

The operation panel and reconnect behavior are useful, but generic extraction of `command`, `path`, `query`, `url`, `prompt`, `content`, partial results, and results can persist credentials or sensitive content into Run events and checkpoints.

Required redesign:

- default-deny persistence of raw tool arguments and outputs;
- optional, tool-owned, explicitly sanitized display metadata;
- no full Bash command persistence;
- URL userinfo/query/fragment removal and workspace-relative path display;
- prompt/content/query treated as sensitive by default;
- regression tests for bearer tokens, API keys, signed URLs, private keys, credential paths, and secret-bearing tool output;
- keep timing/tool-name based running/waiting/stalled UI derivation separate from sensitive summaries.

A blocking review comment was posted on the PR.

## Resulting control boundary

The normal input path remains:

`Web input -> Session Supervisor Inbox -> durable TaskRun -> AgentService/Pi attempt`

The merged `Run now` action selects a queued Inbox item and creates its durable TaskRun immediately. It does not bypass TaskRun or send arbitrary input directly to Pi. Direct run steering/follow-up remain separate control APIs.

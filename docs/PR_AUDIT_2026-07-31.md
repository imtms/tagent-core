## Merged

### PR #3 — Avoid historical blocked Runs freezing the queue

URL: https://github.com/imtms/tagent-core/pull/3

Merge commit: `36d2fbe`

Decision: merge.

Automatic Session inbox dispatch now treats any running Run as active, but only lets the latest blocked/interrupted Run hold the queue. Older blocked/interrupted Runs remain durable for audit and manual recovery without permanently freezing newer Session work.

### PR #2 — Manually start a queued Supervisor input

URL: https://github.com/imtms/tagent-core/pull/2

Merge commit: `87015c5`

Decision: merge.

Adds `POST /api/sessions/:id/inbox/:itemId/start` and a Web `Run now` action. The claim, TaskRun creation, and Inbox binding are transactional. A running Run or active continuation still prevents concurrent execution. Continuation claim also checks for another running Run in the same Session.

This is an explicit human override of automatic blocked/interrupted priority, not a direct Pi prompt path: the selected Inbox item still becomes a durable TaskRun before Pi execution.

### PR #4 — Show latest TaskRun state in the workspace list

URL: https://github.com/imtms/tagent-core/pull/4

Merge commit: `7e3dae7`

Decision: merge.

Session summaries expose `latestRunStatus` and `latestRunPhase` through a correlated latest-Run query. The Web Session rail refreshes and displays compact status metadata without a schema migration or application-layer N+1 query.

### PR #5 — Safe persisted current-operation state

URL: https://github.com/imtms/tagent-core/pull/5

Merge commit: `99dde93`

Decision: merge after revision `5c0dc8d`.

The original implementation was blocked because it persisted generic command, path, URL, prompt/content, and tool-result summaries. The revised implementation removes raw arguments and results from runtime events and checkpoints. It stores only tool identity and activity timestamps, allowing the Web UI to derive running/waiting/possibly-stalled presentation without widening the credential boundary.

### PR #6 — Retry an Inbox launch on the same TaskRun

URL: https://github.com/imtms/tagent-core/pull/6

Merge commit: `10a3426`

Decision: merge.

Runtime initialization failure is now distinguished from ordinary execution failure. A retryable launch failure keeps the original Inbox item and TaskRun, atomically increments the attempt, avoids duplicating the user message, and remains fenced against another running Run or active continuation in the Session.

## Changes requested

### PR #1 — Immutable production artifact and native dependency deployment

URL: https://github.com/imtms/tagent-core/pull/1

Decision: do not merge yet.

Revision `fe600d9` resolves the original native-binding tests, old-release rollback, tar-entry validation, and full-file manifest requirements. One first-deployment boundary remains: if no previous `current` symlink exists, restart or health failure leaves the newly selected failing `current` in place. The rollback path must restore the original no-`current` state and cover restart and health failures with tests.

A second blocking review comment was posted on the PR.

### PR #7 — Edit and reorder queued Supervisor inputs

URL: https://github.com/imtms/tagent-core/pull/7

Decision: do not merge yet.

The queued-only Store mutations and complete-ID-set transactional reorder are acceptable, but the new Web component removes the existing Defer/Resume and Merge-first actions. The feature must preserve those controls, coordinate busy/fencing state across all item mutations, and preferably provide keyboard-accessible move actions in addition to drag-and-drop. The branch also conflicts with the updated main Web styles.

### PR #8 — Rename workspaces

URL: https://github.com/imtms/tagent-core/pull/8

Decision: do not merge yet.

The Session rename API and Store behavior are acceptable, but Escape cancellation races with unconditional blur-save: the blur closure can retain the pre-Escape draft and submit a rename after cancellation. Enter should save explicitly, Escape must suppress subsequent blur submission, and executable interaction tests should cover Escape, Enter, empty titles, and single-submit behavior. The branch also conflicts with the updated main Web state test.

## Resulting control boundary

The normal input path remains:

`Web input -> Session Supervisor Inbox -> durable TaskRun -> AgentService/Pi attempt`

The merged `Run now` action selects a queued Inbox item and creates its durable TaskRun immediately. It does not bypass TaskRun or send arbitrary input directly to Pi. Direct run steering/follow-up remain separate control APIs.
